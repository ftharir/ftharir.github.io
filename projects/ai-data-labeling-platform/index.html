Overview

Models for speech recognition (ASR), text in images (OCR) and vehicle attributes all need labeled data, and labeling everything by hand is slow and uneven. This platform makes the work faster and more reliable: AI proposes labels (pseudo-labels), people correct them, and quality-control workflows check the result.

I owned the project end to end during the 12-week internship: system design, application structure, database schema, authentication, the core workflows and deployment.

Approach

  1. 1

    System design

    Application structure, database schema and authentication designed first, so the three data types could share one platform.

  2. 2

    Multimodal annotation

    A Streamlit interface supports three pipelines: ASR (audio), OCR (images with text) and vehicle attribute recognition.

  3. 3

    AI pseudo-labeling

    A model pre-labels each item, so annotators start from a proposal instead of a blank field.

  4. 4

    Human in the loop

    Annotators review and correct the proposals; the corrections are what end up in the dataset.

  5. 5

    Quality control

    Dedicated workflows check labeled items before they are accepted.

  6. 6

    Deployment

    Packaged with Docker and Docker Compose, backed by PostgreSQL through SQLAlchemy.

Key decisions

Pseudo-labels plus people

Fully automatic labels propagate the model's own mistakes; fully manual labels are slow. The combination keeps speed and accountability.

One platform for three modalities

Shared users, projects, datasets and review workflows, with a pipeline per data type, instead of three separate tools.

Quality control as a first-class workflow

Review is part of the data model and the interface, not an afterthought.
