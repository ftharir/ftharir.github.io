Overview

Captcha text is distorted and the characters touch, so segmenting it into letters is fragile. This project reads the whole image at once: a convolutional network extracts features, a bidirectional GRU reads them as a sequence and a CTC loss lets the network learn the alignment between the image and the five characters without any segmentation.

It began as a course project and was rebuilt with a corrected training and evaluation pipeline: a fixed split, a held-out test set that is never used for model selection, per-epoch history, error analysis and unit tests.

Approach

  1. 1

    Data and split

    1,070 captchas split 80 / 10 / 10 with a fixed seed: 856 train, 107 validation, 107 test.

  2. 2

    Model

    A CNN feature extractor followed by a bidirectional GRU and a CTC output layer, in PyTorch. The character set is derived from the file names and saved next to the model.

  3. 3

    Training

    150 epochs in about 25 minutes on an RTX 3050 laptop GPU; the first ~20 epochs are the plateau typical for CTC models.

  4. 4

    Select and evaluate

    The best model by validation accuracy is kept, then evaluated once on the held-out test set.

  5. 5

    Verify

    Training, evaluation and prediction scripts, per-epoch history, an error table and 9 unit tests.

Key decisions

CTC instead of segmentation

No character cutting: the network learns where the characters are.

A test set that stays untouched

Model selection uses validation only, so the test numbers are not tuned.

Report the uncertainty

With 107 test images the 95 % confidence interval for exact match is roughly 94.9 % to 99.8 %, so the point estimate should not be read as more precise.

Limitations, stated openly

  • The only test error is 'ecd4w' read as 'cd4w' (the first character was missed).
  • One captcha style and 107 test images: the model has not been tested on other generators or fonts.

What is next

  • Test on captchas from other generators and with more noise.
  • Add data augmentation and a larger test set.
